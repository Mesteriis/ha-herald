# Настройки интеграции

Откройте Herald в **Настройки → Устройства и службы**, затем его параметры.
Вместо общей длинной формы появится меню из пяти разделов. Выберите раздел,
измените нужные поля и сохраните. Сохранение закрывает окно параметров;
чтобы изменить другой раздел, откройте параметры снова.

Форма показывает текущие действующие значения. Сохраняются только поля,
которые вы изменили в открытом разделе. Остальные параметры, включая настройки
других каналов и потоков, сохраняются. Закрытие формы без сохранения ничего не
меняет. Изменённые параметры применяются при автоматической перезагрузке
интеграции.

## Тихие часы

Укажите начало и конец в формате `ЧЧ:ММ`, например `23:00` и `07:00`.
Используется местное время Home Assistant; интервал может переходить через полночь.
Тихие часы не означают полное отключение уведомлений: результат зависит от
важности, настроек каналов и правил отдельных уведомлений.

## Генерация текста

Выберите **Ollama** или **OpenAI-совместимый API**, укажите базовый адрес сервера
и точный идентификатор модели. Для OpenAI-совместимого API нужен HTTPS-адрес
(например, `https://ai.sh-inc.ru`) и ключ API. Herald отправляет запросы на
`/v1/chat/completions`; базовый адрес может оканчиваться на `/v1`. Ключ вводится
в поле пароля и не показывается повторно. Пустое поле сохраняет уже
записанный ключ; новый ключ заменяет его. Сохранение не включает ИИ и не
проверяет доступность сервера, ключа или модели. Включение управляется
отдельным переключателем Herald. Даже при включённом ИИ генерация зависит от
настроек конкретного запроса и потока.

Если ключ должен храниться в секретах Home Assistant, добавьте его в
`secrets.yaml` под выбранным именем и укажите ссылку в `configuration.yaml`:

```yaml
herald:
  ollama:
    api_key: !secret herald_omniroute_api_key
```

Провайдер, адрес и модель могут оставаться в параметрах интеграции. Не
вводите тот же ключ в поле пароля: значение из параметров имеет приоритет над
YAML. После изменения YAML проверьте конфигурацию Home Assistant и перезапустите
его. Само значение ключа не добавляйте в репозиторий или документацию.

При использовании внешнего API текст уведомления и контекст, включённые в
промпт, передаются выбранному серверу. Если ключ отсутствует, запрос
завершается ошибкой или ответ не содержит ожидаемого JSON, Herald использует
исходный текст или локальную сводку. Старые настройки без поля провайдера
по-прежнему используют Ollama.

## Каналы доставки

Сначала выберите существующий канал. Затем доступны два поля:

- **Канал включён** — разрешает использование канала. Выключенный канал
  исключается из обычной доставки.
- **Минимальная важность** — обычные уведомления ниже этого порога пропускаются.

Общие ограничения и правила уведомлений продолжают действовать. Включённый
канал не означает подтверждённую доставку на устройство. Явный разрешённый
тест канала может обойти его выключение и порог важности.

Здесь нельзя создать новый канал, изменить его транспорт или настроить учётные
данные провайдера. Если каналы не найдены или выбранный канал исчез, проверьте
конфигурацию и откройте параметры заново. Для локальной проверки каналов без
отправки используйте [карточку управления Herald](channel_setup.md).

## Доставка по занятым комнатам

В YAML можно задать `presence.occupied_room_routing: true`. Тогда `voice_auto`
разворачивается в отдельные TTS-каналы с полем `room` для **каждой** комнаты,
чей датчик из `presence.room_sensors` показывает `on`. Если в комнате нет
настроенного или доступного голосового устройства, звук в другой комнате не
воспроизводится. Личный режим тишины получателя также может подавить голос,
даже когда комната занята. Автоматически найденная основная комната не сужает
рассылку до одной комнаты; явно указанная в запросе комната сужает.
Включённый телевизор сам по себе не считается доказательством
присутствия. TV-канал с тем же `room` добавляется отдельно от голоса и должен
иметь `data.active_only: true`, чтобы выключенный телевизор не получал сообщение.
Явно выбранная комната также требует подтверждённой занятости.

Для удалённых адресатов можно задать
`presence.remote_channels_away_only: true`. Мобильные и Telegram-каналы тогда
разрешены только когда датчик `presence.nobody_home_entity` показывает `on` и
все участники `presence.family_group` имеют известное состояние вне дома.
Неизвестное или недоступное состояние не считается подтверждённым отсутствием.
Необязательный список `presence.allowed_remote_channels` ограничивает точные
имена разрешённых мобильных и Telegram-каналов. Эти ограничения действуют и
для явного списка каналов или принудительного вызова.

Telegram Bot с сущностью `notify.*` настраивается каналом типа `telegram`,
сервисом `notify.send_message` и `entity_id` этой сущности. Для других версий
Telegram Bot остаётся доступен прежний сервис `telegram_bot.send_message`.
При переопределении списка `flows.<name>.channels` остальные стандартные
свойства потока, включая важность и политику сводки, сохраняются.

## Потоки уведомлений

Выберите существующий поток. Настройки действуют для этого потока:

| Поле | Поведение |
| --- | --- |
| Персонаж сводки | Переопределяет персонажа для сводок. Пустое значение убирает переопределение: используется персонаж запроса, потока или персонаж по умолчанию. Само по себе это поле не включает сводки. |
| Интервал между доставками, с | Пропускает уведомления в течение указанного времени после последней доставки потока. |
| Подавление повторов, с | Пропускает совпадающие повторные события внутри указанного окна. Совпадение учитывает не только текст, но и параметры уведомления. |

Интервалы задаются целыми секундами от `0` до `86400`. `0` отключает
соответствующий фильтр. Пропущенные таким образом уведомления не ставятся
на отложенную отправку. Правило отдельного уведомления может переопределить
интервал доставки, а поле `suppress` запроса — окно подавления повторов.
Специальные запросы с `force: true` могут обходить эти два фильтра.

Персонаж, уже указанный в настройке, остаётся доступен для выбора, даже если
его определение сейчас недоступно. Это сохраняет настройку и не подтверждает,
что шаблон персонажа загружен.

## Режим обслуживания

**Внешняя сущность режима обслуживания** задаёт необязательный идентификатор
сущности, состояние `on` которой активирует обслуживание. Пустое поле убирает
эту внешнюю связь. Собственный переключатель режима обслуживания Herald
остаётся доступен.

Прежний параметр `maintenance_min_level` и его сущность сохранены для
совместимости. В текущей реализации этот параметр не фильтрует уведомления,
перенаправленные при обслуживании, поэтому новая форма его не редактирует.
Режим активен, если включена внешняя сущность или собственный переключатель
обслуживания Herald. При активном обслуживании
обычные каналы заменяются уведомлением Home Assistant и системным журналом;
остальные ограничения продолжают действовать.

## Где проверять результат

Для текущих состояний каналов, общих ограничений и источников значений используйте
[настройку каналов](channel_setup.md). Для вопроса «как будет обработано это
конкретное уведомление» откройте [редактор правил](rule_editor.md) и выполните
проверку без отправки. Локальная проверка не подтверждает физическую доставку
или доступность внешнего провайдера.
